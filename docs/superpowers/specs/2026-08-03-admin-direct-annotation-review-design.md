# 管理员直接修改标注结果设计

## 目标

让管理员在审核页面直接编辑每条已有标注的录音并完成审核，也可按需领取任务用于多人协作锁定。该设计取代原有“至少两份标注后仲裁生成独立最终结果”的 ASR 审核方式。

## 入队规则

- 一条录音只要至少有一名标注员成功保存音频片段标注，就进入审核队列。
- 同一录音存在多名标注员结果时，每个“录音 + 标注员”组合都是一条独立审核记录。
- 完全没有已保存标注的录音不进入队列。
- 已审核记录继续显示在“已完成”列表中，不重复创建。

## 领取规则

- 每条待审核记录下方显示“分配给自己”按钮。
- 管理员领取后记录管理员账号和领取时间，状态改为“审核中”。
- 已由其他管理员领取的记录只读显示，不能再次领取。
- 领取是可选的多人协作锁定，不是编辑、保存或审核通过的前置条件。
- 当前只有 `admin` 一个管理员，但数据结构仍保存领取人，便于后续增加管理员。

## 编辑与保存

- 待审核记录可直接编辑片段开始时间、结束时间、说话人、转写文本和方言标记。
- 当前管理员领取后的记录仍可编辑；其他管理员已经领取的记录只读。
- “保存修改”直接覆盖该标注员在 `UserState` 中的 `transcript_segments:_data` 原始值，并同步现有可读 JSON 输出。
- 保存前把完整旧值写入审核历史快照，包含录音编号、标注员、管理员、时间和修改前数据。
- 片段按开始时间升序保存；开始时间不得小于零，结束时间必须大于开始时间。
- 保存修改不会自动完成审核，管理员仍需点击“审核通过”。

## 审核状态

- 状态为 `pending`、`in_progress` 或 `completed`。
- 待审核记录可直接“审核通过”，此时自动把当前管理员记录为审核人，但不必先转为“审核中”。
- “审核通过”记录管理员和完成时间；完成后默认只读。
- 已完成记录如需再次修改，管理员先点击“重新编辑”，状态回到“审核中”，再次保存时继续生成历史快照。
- 服务重启后领取状态、审核状态和历史快照均保留。

## 存储

- 标注正文仍保存在现有标注员 `user_state.json` 中，不迁移到 `project.sqlite`。
- 审核状态与修改历史保存在项目 `annotation_output/admin_review/` 下的独立 JSON 文件中。
- 使用原子写入，避免中途退出破坏审核状态文件。

## 页面与权限

- 复用 `/adjudicate` 页面和现有管理员审核权限。
- 页面以录音编号和标注员分组展示，包含播放、片段编辑、领取、保存、审核通过和重新编辑。
- 普通标注员不能读取审核数据、领取任务或修改其他人的标注。
- 所有提示和按钮使用中文。

## 导出

- 管理后台“标注数据”的 JSON 和 SQLite 导出继续读取标注员原始数据，因此自动包含管理员覆盖后的内容。
- 导出记录增加审核状态、审核管理员和审核完成时间。
- 未审核数据仍可导出，但明确标记为 `pending` 或 `in_progress`。

## 验收标准

1. 任意标注员保存一条录音后，该“录音 + 标注员”记录进入审核队列。
2. 管理员可领取未分配记录，其他管理员不能重复领取。
3. 未领取的待审核记录可以直接编辑、保存或审核通过。
4. 已由其他管理员领取的记录不能编辑、保存或审核通过。
5. 管理员修改片段后，标注员原始状态文件和标注数据页面立即显示新值。
6. 每次覆盖前均保留可追溯旧值，且重启后仍存在。
7. 保存修改与审核通过是两个独立动作。
8. JSON、SQLite 导出包含修改后数据及审核状态。
9. 普通标注员访问新增审核接口返回无权限。

## 非目标

- 不为未标注录音生成空审核任务。
- 不保留独立的管理员最终标注副本。
- 不把管理员加入普通标注任务分配或配额统计。
- 不扩展非音频标注类型的直接编辑能力。
